## Purpose

该能力把算法题和其他面试题统一沉淀为可检索的个人记忆，完整保留题干、多次作答、错因、复盘和图片上下文，并提供适合 Web 端持续录入与回顾的工作流。

## ADDED Requirements

### Requirement: Web 学习工作区
[MVP] 系统 MUST 提供中文 Web 工作区，并提供仪表盘、题库、题目工作台、RAG 问答、复习队列和设置六个稳定主入口；尚未交付阶段的功能 MUST 明确标记为不可用，不得伪装成可操作功能。

#### Scenario: 从仪表盘进入题库
- **WHEN** 用户启动应用并从仪表盘选择题库入口
- **THEN** 系统展示题目列表、搜索和筛选操作，并保持主导航位置稳定

#### Scenario: 访问尚未交付的阶段功能
- **WHEN** 当前安装版本尚未包含 Phase 2 或 Phase 3 能力
- **THEN** 系统明确显示该能力尚未启用，且不展示会丢失输入的虚假操作

### Requirement: 统一题目记录
[MVP] 系统 MUST 以 `QuestionRecord` 语义记录题目，至少包含唯一标识、标题、题型、Markdown 题干、难度、来源名称、来源 URL、自定义标签、创建时间、更新时间和归档状态。

#### Scenario: 创建算法题
- **WHEN** 用户选择 `algorithm` 题型并填写标题和题干
- **THEN** 系统创建具有唯一标识的题目，并允许记录代码语言、约束、示例和复杂度相关内容

#### Scenario: 创建非算法题
- **WHEN** 用户选择 `knowledge`、`system_design`、`behavioral` 或 `other` 题型
- **THEN** 系统使用相同核心字段保存题目，并展示适合该题型的补充输入区域

#### Scenario: 缺少必填字段
- **WHEN** 用户在标题或题干为空时提交题目
- **THEN** 系统阻止保存并在对应字段附近说明缺失内容

### Requirement: 题型模板保持可编辑
[MVP] 系统 MUST 为 `algorithm`、`knowledge`、`system_design`、`behavioral` 和 `other` 提供起始模板，同时 MUST 允许用户自由编辑最终 Markdown 内容，模板不得限制记录真实面试上下文。

#### Scenario: 使用系统设计模板
- **WHEN** 用户创建 `system_design` 题目
- **THEN** 系统提供需求、约束、架构、权衡和扩展性等起始段落，且每个段落均可删除或修改

#### Scenario: 切换已有题目的题型
- **WHEN** 用户把已有题目切换为另一题型
- **THEN** 系统保留已有内容并仅提供新模板建议，不得静默覆盖正文或作答

### Requirement: 题目生命周期管理
[MVP] 系统 MUST 支持查看、编辑、归档、恢复和永久删除题目；归档题默认不出现在活动题库和复习候选中，永久删除必须经过明确确认。

#### Scenario: 编辑题目
- **WHEN** 用户修改题干、难度、来源或标签并保存
- **THEN** 系统保留题目标识和既有作答关系，并更新修改时间

#### Scenario: 归档并恢复题目
- **WHEN** 用户归档题目后切换到归档视图并选择恢复
- **THEN** 系统重新将题目显示在活动题库中，且历史作答和复盘保持不变

#### Scenario: 永久删除题目
- **WHEN** 用户确认永久删除题目
- **THEN** 系统删除该题目的作答、错因、复盘、索引内容和仅被该题引用的托管附件

### Requirement: Markdown 与本地图片
[MVP] 系统 MUST 在题干、作答和复盘中支持 Markdown、代码块和本地图片；粘贴或选择的图片 MUST 被复制到应用管理的本地附件区，并以可迁移引用关联到所属记录。

#### Scenario: 粘贴本地图片
- **WHEN** 用户在 Markdown 编辑器中粘贴一张受支持的图片
- **THEN** 系统保存附件、插入可预览引用，并在重新启动应用后仍能显示图片

#### Scenario: 附件读取失败
- **WHEN** 托管图片缺失或损坏
- **THEN** 系统保留 Markdown 文本并显示明确的附件不可用状态，不得导致整条题目无法打开

#### Scenario: 删除仍被引用的附件
- **WHEN** 用户尝试删除仍被其他内容引用的图片
- **THEN** 系统说明引用位置并要求用户确认，不得静默破坏其他记录

### Requirement: 多次作答记录
[MVP] 系统 MUST 使用 `AnswerAttempt` 语义为同一题目保存任意多次作答，每次至少包含唯一标识、关联题目标识、Markdown 思路或答案、可选代码与语言、结果、可选耗时、创建时间和更新时间。

#### Scenario: 保存一次错误作答
- **WHEN** 用户把本次结果标记为 `incorrect` 并保存答案
- **THEN** 系统把该作答追加到题目历史中，不覆盖以前的作答

#### Scenario: 保存部分正确或正确作答
- **WHEN** 用户选择 `partial` 或 `correct`
- **THEN** 系统按所选结果保存，并在题目历史中清楚区分每次结果和时间

#### Scenario: 保存跳过记录
- **WHEN** 用户选择 `skipped` 且未填写答案正文
- **THEN** 系统允许保存该次练习记录，但不得把它展示为已正确完成

### Requirement: 错因与复盘
[MVP] 系统 MUST 使用 `MistakeReview` 语义关联一次或多次作答，记录错因分类、自由复盘、修正思路、关键结论和用户确认保存的 AI 内容来源。

#### Scenario: 为错题创建复盘
- **WHEN** 用户从错误作答进入复盘并填写错因和修正思路
- **THEN** 系统将复盘关联到该题和对应作答，并在题目详情中可再次编辑

#### Scenario: 保存 AI 生成内容
- **WHEN** 用户确认保存一段 AI 诊断或总结
- **THEN** 系统将其标记为 AI 来源并写入复盘；未确认的临时输出不得进入长期记录

### Requirement: 题库搜索与筛选
[MVP] 系统 MUST 支持按标题、题干、作答、错因和复盘执行本地关键词搜索，并可按题型、难度、结果、标签、来源、归档状态和是否错题组合筛选。

#### Scenario: 组合查找错题
- **WHEN** 用户搜索关键词并同时选择算法题、困难和错误结果筛选
- **THEN** 系统只返回同时符合全部条件的题目，并清楚显示当前筛选条件

#### Scenario: 搜索无结果
- **WHEN** 没有题目符合关键词和筛选条件
- **THEN** 系统展示空结果状态，并允许一键清除筛选或新建题目

### Requirement: 题目详情可追溯
[MVP] 系统 MUST 在题目工作台中按时间展示全部作答、错因、复盘、AI 来源标识和复习摘要，并允许用户从相关内容返回原始记录。

#### Scenario: 查看历史演进
- **WHEN** 用户打开做过多次的题目
- **THEN** 系统按时间展示每次作答及对应结果，且不会把不同作答合并成一份无来源答案
