## Purpose

该能力在不替代用户思考的前提下，为当前题目提供可控的渐进提示和结构化作答诊断，并把提示使用与用户确认的改进内容沉淀到个人学习记录中。

## ADDED Requirements

### Requirement: 显式启动 AI 辅助
[Phase 2] 系统 MUST 仅在用户从题目工作台显式请求提示或诊断时调用聊天模型，并在发送前明确本次使用的题目、作答和历史上下文范围。

#### Scenario: 请求当前作答提示
- **WHEN** 用户在一次未完成作答中选择请求提示
- **THEN** 系统仅发送当前题目、当前草稿和用户选择包含的相关历史，不自动发送其他无关题目

#### Scenario: 未配置可用聊天模型
- **WHEN** 用户请求 AI 辅助但没有已验证的聊天模型
- **THEN** 系统不发送请求，并提供进入模型设置的操作，同时保留当前作答草稿

### Requirement: 渐进式提示
[Phase 2] 系统 MUST 提供至少三个由浅入深的提示级别：澄清或反问、方向或关键突破点、详细步骤或伪代码；首次请求不得默认直接展示完整答案。

#### Scenario: 获取第一级提示
- **WHEN** 用户首次请求提示
- **THEN** 系统优先通过问题澄清、边界提醒或启发性反问引导思考，不直接给出完整解法

#### Scenario: 主动升级提示
- **WHEN** 用户明确选择更详细的下一等级提示
- **THEN** 系统基于已有提示继续展开，并清楚标识当前提示等级

#### Scenario: 用户直接请求完整解法
- **WHEN** 用户明确选择查看详细步骤或参考解法
- **THEN** 系统在确认这会暴露解题路径后生成对应内容，并记录所使用的最高提示等级

### Requirement: 提示使用记录
[Phase 2] 系统 MUST 把每次提示请求、提示等级、生成内容、模型来源和时间关联到当前 `AnswerAttempt`，同时允许用户删除单条提示记录。

#### Scenario: 保存使用过的提示
- **WHEN** 一次提示成功生成
- **THEN** 系统将其显示在当前作答的辅助记录中，并在之后查看该作答时可追溯

#### Scenario: 删除提示记录
- **WHEN** 用户确认删除一条提示
- **THEN** 系统从该作答的辅助历史和后续上下文中移除它，不修改作答正文

### Requirement: 结构化作答诊断
[Phase 2] 系统 MUST 根据题型生成结构化诊断；算法题至少覆盖思路正确性、潜在缺陷、时间复杂度、空间复杂度、边界情况、可读性和改进方案，其他题型至少覆盖完整性、准确性、结构、遗漏点和改进表达。

#### Scenario: 诊断算法题代码
- **WHEN** 用户提交包含代码的算法题作答并请求诊断
- **THEN** 系统逐项展示正确性风险、复杂度、边界情况和改进建议，并将无法确定的结论标为不确定

#### Scenario: 诊断行为面试答案
- **WHEN** 用户对 `behavioral` 题型请求诊断
- **THEN** 系统围绕情境、任务、行动、结果和表达清晰度反馈，而不是输出算法复杂度字段

#### Scenario: 作答内容不足
- **WHEN** 用户请求诊断但当前作答不足以分析
- **THEN** 系统指出缺少的内容并停止生成正式结论，不得把猜测保存为诊断结果

### Requirement: 静态分析边界
[Phase 2] 系统 MUST 明确说明算法代码诊断来自模型静态分析，未实际执行代码或测试用例，不得把推测描述为已经通过运行验证。

#### Scenario: AI 判断代码可能正确
- **WHEN** 模型未发现明显错误
- **THEN** 系统使用“静态分析未发现”之类的限定表述，并提示代码未实际运行

#### Scenario: 用户要求运行代码
- **WHEN** 用户要求应用执行代码或测试用例
- **THEN** 系统说明当前版本不支持执行，并保留代码供用户编辑或导出

### Requirement: AI 内容确认后沉淀
[Phase 2] 系统 MUST 把生成的诊断、优化思路和参考答案作为临时草稿展示，允许用户编辑和选择保存范围；只有用户确认保存的内容才可写入 `MistakeReview` 并进入 RAG 语料。

#### Scenario: 选择性保存诊断
- **WHEN** 用户只选择保存“边界情况”和“关键结论”两部分
- **THEN** 系统仅把所选且可编辑的内容写入复盘，并标记模型来源和保存时间

#### Scenario: 放弃诊断草稿
- **WHEN** 用户关闭或丢弃未保存的诊断
- **THEN** 系统不得将其加入复盘、索引或后续个人记忆回答

### Requirement: AI 请求可取消且不破坏作答
[Phase 2] 系统 MUST 允许取消提示或诊断请求，并在超时、限流、协议错误或网络失败时保留当前作答和已填写复盘。

#### Scenario: 诊断生成失败
- **WHEN** 模型调用返回限流或超时
- **THEN** 系统显示可重试错误和所用模型档案，不修改或清空用户作答

#### Scenario: 切换模型后重试
- **WHEN** 用户在失败后选择另一已验证聊天模型并重试
- **THEN** 系统使用新模型重新发起请求，并分别标识两次请求状态
