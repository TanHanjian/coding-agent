## Purpose

该能力把个人题库构建为可维护、可切换模型且可追溯的 RAG 记忆层，使用户能够检索过去的思路和错误经验，同时明确区分个人证据与模型通用知识。

## ADDED Requirements

### Requirement: Go Agent 服务边界
[MVP] 系统 MUST 由 Go 后端统一编排模型端点、个人记忆检索、提示构建、回答生成和会话持久化；React Web 前端 MUST 通过后端 API 访问这些能力，不得直接访问 SQLite 或模型凭据。Go 服务 MUST 提供健康检查，并默认仅监听本机地址。

#### Scenario: 后端服务不可用
- **WHEN** Web 前端无法连接 Go 后端
- **THEN** 系统显示服务不可用状态，保留本地未提交输入，并允许用户重试连接

#### Scenario: 用户请求流式回答
- **WHEN** 用户显式提交 RAG 问题
- **THEN** Go Agent 通过流式 API 返回回答片段、引用和完成状态，前端不得自行拼装模型请求

### Requirement: 多模型端点配置
[MVP] 系统 MUST 使用 `ModelEndpointProfile` 语义保存多个 OpenAI 兼容端点，至少包含唯一标识、显示名称、Base URL、聊天模型名、嵌入模型名、非密钥参数和安全凭据引用；聊天端点与嵌入端点 MUST 可独立选择。

#### Scenario: 保存两个模型档案
- **WHEN** 用户分别配置在线端点和本地兼容端点
- **THEN** 系统保存两个可命名档案，并允许独立选择其中任意聊天模型和嵌入模型

#### Scenario: 配置缺少必要信息
- **WHEN** 用户未填写 Base URL 或所需模型名就启用档案
- **THEN** 系统阻止启用并指出缺失字段，不得发起不完整请求

### Requirement: 模型连接验证
[MVP] 系统 MUST 为聊天和嵌入能力提供独立的连接测试，并用可操作的中文错误区分认证失败、地址不可达、模型不存在、协议不兼容和请求超时。

#### Scenario: 连接测试成功
- **WHEN** 用户测试一个有效的 OpenAI 兼容端点
- **THEN** 系统分别显示已验证的聊天或嵌入能力以及验证时间

#### Scenario: API Key 无效
- **WHEN** 端点返回认证失败
- **THEN** 系统提示用户更新凭据，不得在界面、错误详情或日志中显示完整 API Key

### Requirement: 个人记忆语料范围
[MVP] 系统 MUST 仅把活动题目的题干、个人作答、错因、复盘笔记及用户确认保存的 AI 总结纳入个人记忆语料；归档题可由用户选择纳入，临时 AI 输出和已删除内容 MUST 排除。

#### Scenario: 保存复盘后更新语料
- **WHEN** 用户新增或修改一份复盘
- **THEN** 系统将相关内容标记为待索引，并在索引完成后可通过 RAG 检索到新版本

#### Scenario: AI 输出未被确认
- **WHEN** AI 已生成诊断但用户未执行保存
- **THEN** 该输出不会进入索引，也不会在后续回答中被描述为个人记忆

#### Scenario: 删除题目后清理语料
- **WHEN** 用户永久删除题目
- **THEN** 系统移除该题目对应的全文和向量索引，使后续检索不再返回它

### Requirement: 混合检索
[MVP] 系统 MUST 同时利用本地关键词相关性和向量语义相关性检索个人语料，并允许按题型、标签、难度和时间范围缩小 RAG 查询范围。

#### Scenario: 使用同义表达查询
- **WHEN** 用户用不同于原笔记的表达询问一个已记录概念
- **THEN** 系统能够通过语义检索返回相关个人记录，并保留关键词命中的可解释信息

#### Scenario: 使用题型过滤查询
- **WHEN** 用户把 RAG 查询范围限制为系统设计题
- **THEN** 检索候选与最终引用不得包含其他题型的记录

### Requirement: 可追溯 RAG 回答
[MVP] 系统 MUST 使用 `RagCitation` 语义为基于个人记忆的关键结论提供引用，引用至少包含题目标识、题目标题、内容类型、内容片段定位和相关摘录。

#### Scenario: 回答命中个人错因
- **WHEN** 回答引用了用户过去记录的错误原因
- **THEN** 对应结论旁显示可识别引用，用户选择引用后直接打开题目及相关错因或作答位置

#### Scenario: 引用目标已不可用
- **WHEN** 用户打开的历史回答引用已删除内容
- **THEN** 系统明确显示引用已失效，不得跳转到错误题目或伪造摘录

### Requirement: 区分个人记忆与通用补充
[MVP] 系统 MUST 优先根据检索到的个人证据回答；证据不足时可以使用模型通用知识补充，但 MUST 使用独立的“通用补充”区域并声明其不来自个人题库。

#### Scenario: 个人证据充足
- **WHEN** 检索内容足以支持回答
- **THEN** 系统以个人记忆为主体回答并附引用，不添加无必要的通用内容

#### Scenario: 个人证据不足
- **WHEN** 个人语料无法完整回答问题
- **THEN** 系统说明证据不足，并把任何模型补充内容与个人记忆结论清楚分开

#### Scenario: 没有个人证据且模型补充失败
- **WHEN** 检索无结果且模型请求失败或未配置
- **THEN** 系统明确说明当前无法回答，并提供返回题库搜索或检查模型设置的操作

### Requirement: 嵌入模型切换与索引重建
[MVP] 系统 MUST 在用户切换活动嵌入端点或模型时创建全量重建任务，显示总量、已处理数量、失败数量、当前状态和取消操作；不同嵌入模型生成的向量 MUST 不得混用。

#### Scenario: 成功切换嵌入模型
- **WHEN** 新模型完成全量重建且所有必要索引可用
- **THEN** 系统原子地启用新索引，并将后续查询发送给新嵌入模型

#### Scenario: 重建过程中查询
- **WHEN** 新索引仍在构建且旧索引可用
- **THEN** 系统继续使用旧模型与旧索引回答，并明确显示切换尚未完成

#### Scenario: 重建失败或取消
- **WHEN** 新索引重建失败或用户取消
- **THEN** 系统保留旧活动索引，展示失败原因和重试入口，不得留下可被查询的混合索引

### Requirement: 增量索引状态
[MVP] 系统 MUST 展示个人语料的索引状态，包括未配置、待索引、索引中、就绪和失败，并允许用户对失败项重试。

#### Scenario: 编辑题目后增量更新
- **WHEN** 已索引题目被修改
- **THEN** 系统保留旧内容可用直到新内容索引成功，随后用新版本替换旧版本

#### Scenario: 单条内容索引失败
- **WHEN** 嵌入端点只对部分内容返回错误
- **THEN** 系统记录失败项、继续处理其他内容并显示可重试数量

### Requirement: 流式回答与取消
[MVP] 系统 MUST 流式展示模型回答，允许用户取消进行中的请求，并在失败时保留用户问题和已经接收的可见内容，且不得把不完整回答自动保存为长期记忆。

#### Scenario: 用户取消回答
- **WHEN** 用户在生成过程中选择取消
- **THEN** 系统停止后续生成、标记该回答未完成，并保留重新提问操作

#### Scenario: 网络中断
- **WHEN** 模型流式响应期间连接中断
- **THEN** 系统显示可恢复的错误状态，保留问题与已显示文本，不影响题库本地数据

### Requirement: RAG 会话记录
[MVP] 系统 MUST 在本地保存用户选择保留的 RAG 会话，包括问题、完整回答、引用、所用聊天模型和时间；删除会话不得删除其引用的题目。

#### Scenario: 保存并重新打开会话
- **WHEN** 用户保留一次完成的 RAG 对话并重启应用
- **THEN** 系统恢复对话内容、引用和模型来源信息

#### Scenario: 删除会话
- **WHEN** 用户确认删除一段 RAG 会话
- **THEN** 系统只删除会话记录，不修改题目、作答、复盘或其索引
