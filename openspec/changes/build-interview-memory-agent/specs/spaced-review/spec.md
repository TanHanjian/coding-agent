## Purpose

该能力把错误和薄弱题目转化为基于 FSRS 的可执行复习队列，通过主动回忆、四级评分、到期排序和应用内提醒帮助用户长期巩固个人面试记忆。

## ADDED Requirements

### Requirement: 复习资格管理
[Phase 3] 系统 MUST 在作答结果为 `incorrect` 或 `partial` 时自动为题目创建或恢复 `ReviewState`；结果为 `correct` 的题目仅在用户手动加入时创建复习状态，`skipped` 不自动加入。

#### Scenario: 错题自动入队
- **WHEN** 用户保存一条 `incorrect` 作答
- **THEN** 系统自动将该题加入待复习队列，并在题目详情说明入队原因

#### Scenario: 部分正确题自动入队
- **WHEN** 用户保存一条 `partial` 作答
- **THEN** 系统自动创建复习状态，且不会重复创建多个活动状态

#### Scenario: 正确题手动入队
- **WHEN** 用户对正确完成的题目选择“加入复习”
- **THEN** 系统创建复习状态并安排首次复习

#### Scenario: 跳过题目
- **WHEN** 用户只保存 `skipped` 作答
- **THEN** 系统不自动加入复习，但仍允许用户之后手动加入

### Requirement: 可追溯复习状态
[Phase 3] 系统 MUST 使用 `ReviewState` 语义记录关联题目、当前阶段、下次到期时间、上次复习时间、累计复习次数、遗忘次数和 FSRS 调度所需状态，并向用户显示可理解的到期信息。

#### Scenario: 查看下次复习
- **WHEN** 用户打开已加入复习的题目
- **THEN** 系统显示下次到期日期、最近评分和累计复习次数，不要求用户理解内部算法参数

#### Scenario: 归档题目
- **WHEN** 用户归档一条具有活动复习状态的题目
- **THEN** 系统暂停其到期提醒但保留复习历史，恢复题目后允许继续原有状态

### Requirement: 主动回忆流程
[Phase 3] 系统 MUST 在复习开始时先展示题干并隐藏历史答案、错因、复盘和 AI 建议；用户主动选择揭示后，系统 MUST 展示这些材料并允许评分。

#### Scenario: 开始复习
- **WHEN** 用户打开一条到期复习任务
- **THEN** 系统只展示题干和供用户记录本次回忆的区域，不提前暴露历史答案

#### Scenario: 揭示答案
- **WHEN** 用户完成回忆并选择揭示
- **THEN** 系统展示历史作答、错因和关键复盘，然后启用四级评分操作

### Requirement: 四级评分与 FSRS 调度
[Phase 3] 系统 MUST 接受 `again`、`hard`、`good`、`easy` 四种回忆评分，并使用 FSRS 根据当前状态和评分计算下一次复习时间；评分保存后 MUST 显示新的到期日期。

#### Scenario: 评分 Again
- **WHEN** 用户揭示答案后选择 `again`
- **THEN** 系统记录一次遗忘、安排更近的复习并显示新到期时间

#### Scenario: 评分 Easy
- **WHEN** 用户选择 `easy`
- **THEN** 系统记录本次复习并安排比 `good` 更长的预期间隔

#### Scenario: 关闭而未评分
- **WHEN** 用户揭示答案后退出但没有选择评分
- **THEN** 系统不得改变原到期时间或计入一次完成的复习

### Requirement: 到期队列
[Phase 3] 系统 MUST 按“逾期优先、同日较早到期优先”的稳定顺序展示今日到期队列，并显示逾期、今日、新加入和总待复习数量。

#### Scenario: 同时存在逾期和今日任务
- **WHEN** 用户打开复习队列且两类任务均存在
- **THEN** 系统先展示逾期任务，再展示今日到期任务，并显示各自数量

#### Scenario: 今日没有任务
- **WHEN** 没有逾期或今日到期题目
- **THEN** 系统显示已完成状态及下一次到期日期，不自动拉入未来题目

### Requirement: 本地日期一致性
[Phase 3] 系统 MUST 以运行环境的当前本地时区解释“今日”和到期边界，并在系统时区发生变化后重新计算队列归属，不得修改已经保存的评分历史。

#### Scenario: 跨越本地午夜
- **WHEN** 应用保持打开并跨越本地日期边界
- **THEN** 系统自动刷新今日到期数量和队列，不要求重启应用

#### Scenario: 本地时区变化
- **WHEN** 用户更改系统时区后重新打开复习页
- **THEN** 系统按新本地日期展示到期归属，同时保留每次评分的原始时间

### Requirement: 暂停和移出复习
[Phase 3] 系统 MUST 允许用户暂停、恢复或移出单道题的复习计划；这些操作 MUST 保留历史复习记录，并要求确认会影响后续到期安排。

#### Scenario: 暂停复习
- **WHEN** 用户确认暂停一条复习计划
- **THEN** 该题不再进入到期队列，但题目详情仍显示历史评分和暂停状态

#### Scenario: 恢复复习
- **WHEN** 用户恢复已暂停的复习计划
- **THEN** 系统重新安排下一次复习并说明新的到期日期

### Requirement: 应用内复习提醒
[Phase 3] 系统 MUST 在仪表盘和复习入口显示今日到期数量，并在完成、加入、暂停或评分后即时更新；系统 MUST 不依赖系统级通知或后台常驻。

#### Scenario: 启动应用时有到期任务
- **WHEN** 用户启动应用且存在今日到期题目
- **THEN** 仪表盘和复习入口显示相同的到期数量，并可直接进入队列

#### Scenario: 完成最后一条到期复习
- **WHEN** 用户为今日最后一条任务评分
- **THEN** 到期计数更新为零，并显示今日复习完成状态

### Requirement: 复习历史与统计
[Phase 3] 系统 MUST 保存每次完成复习的评分、时间、调度前后到期时间和关联题目，并在题目详情及仪表盘提供题量、完成量、评分分布和逾期量等基础统计。

#### Scenario: 查看单题复习历史
- **WHEN** 用户在题目详情打开复习历史
- **THEN** 系统按时间显示每次评分及对应的前后到期日期

#### Scenario: 统计不包含未完成会话
- **WHEN** 用户揭示答案但未评分便退出
- **THEN** 仪表盘完成量和评分分布不得计入该次会话
