# Tasks

> [Phase 3] **启动门槛：**本 change 仅用于 Step 1–12 及目标 Workspace 验收完成后的**行为保持式代码优化**。任务 1 未通过时不得执行任务 2–8；遇到必须改变报告、授权、CLI 或 CI 对外行为的需求，先停下并另立 spec。每个任务实施前仍需单独获得修改代码确认。具体新增 Step 10–12 文件以验收后的实际仓库为准。

## 1. 接入完成与行为基线（R0）

- [ ] 1.1 对照 `docs/cozeloop-completion-implementation.md`、Step 10–12 方案和 `evals/cozeloop/acceptance.md` 逐项核查 Step 1–12、内容授权/人工校准、目标 Workspace 的真实实验和 A/B/CI 证据；将缺项及责任人记入基线清单。**验证：**每项有可定位的非敏感证据且无阻断缺项，否则本 change 保持未启动。
- [ ] 1.2 收集已验收命令/flag/退出状态、报告/summary/pending 样本、Prompt 元数据、数据集 item/version、评估器及实验引用、Trace/Usage/授权撤销/CI 分级产物，建立旧版兼容对照表和回归 fixture。**验证：**离线 fixture 测试读取旧数据并对照关键身份/状态；敏感内容不写入仓库。
- [ ] 1.3 核对接入阶段已处理泄露、跨 run 快照、远端内容不可核验及未知写结果等阻断项；复核 Step 10–12 实际新增模块并标记不再成立的拟议抽象。**验证：**design 中的模块责任表与当前真实代码和 Workspace 证据一一对应；阻断项未解决则停止。

## 2. 数据安全与字段契约（R1）

- [ ] 2.1 依据已验收的私有运行报告、受限待上传内容和可分享/CI 摘要，补充敏感 Tool 参数、Judge 理由、Prompt、错误的端到端可见性测试，再分离对应写入/读取责任。**验证：**单元和 CI 产物测试证明各类信息只出现在原验收允许的位置，旧报告依然可读。
- [ ] 2.2 为数据集 schema、实际写入 fields、评估器 Debug 最小化输入和实验字段映射建立受控字段目录/纯投影，先对已有数据做逐字段 golden 测试再替换重复映射。**验证：**每个 manifest 声明字段和值及净化规则逐项与重构前一致，未声明/敏感字段不额外外传。
- [ ] 2.3 将 `infrastructure/cozeloop/consent.go` 中授权记录和待上传载荷存储责任按生命周期分离，保持受限路径、权限、旧格式读取、授权撤销清理的既有结果。**验证：**授权范围/Workspace 不匹配、文件替换/链接、成功删除/失败保留/撤销停止上传的现有与新增测试全部通过，并更新受影响存储说明。

## 3. 身份、状态与恢复编排（R2）

- [ ] 3.1 集中 run/case/version/repeat 身份的构造和一致性校验，用重复、跨 run、缺 case version、多 repeat 的回归样本迁移数据集、报告、实验关联和 A/B 配对调用点。**验证：**与基线相同的有效运行可关联，原本必须拒绝的冲突仍拒绝；新增拒绝规则若改变对外行为先另立 spec。
- [ ] 3.2 将内部授权撤销、身份/版本冲突、部分写入、内容不可核验和未知远端写结果的字符串判断收敛为类型化状态/错误，保留既有 CLI 用户可见消息/退出类别和 pending 迁移语义。**验证：**错误分类、报告与私有状态文件的故障注入测试覆盖写入前、中、后和重启续传；不读取原始平台错误全文。
- [ ] 3.3 将 `cmd/eval` 现有同步/续传的状态转换及已完成的实验提交/续查流程移入相应窄用例，CLI 只处理参数、装配和结果映射。**验证：**使用 fake port 对照旧行为的报告路径、状态、重试、取消、权限撤销和退出码；同步/实验集成测试不再依赖 CLI 内部函数，更新对应操作说明。

## 4. 配置装配与 Trace（R3）

- [ ] 4.1 收敛 server/eval/评估器和新实验命令共享的配置解释、按能力初始化与一次关闭职责，但保留独立开关和各命令专属装配。**验证：**无 CozeLoop 凭据的纯本地路径、Prompt/Trace/Evaluation 开关组合及失败清理测试与基线一致。
- [ ] 4.2 明确 Eino 进程级 Trace Handler 的所有权、重复注册与不同配置冲突处理；通过可注入装配或隔离进程测试，不依赖测试顺序重置包级单例。**验证：**流式 Trace 层级、SDK Close/flush、只注册一次及不同装配场景测试通过；若冲突处理要改变对外行为则暂停并单独评审。
- [ ] 4.3 将通用的 Trace/Usage 关联数据从 `eval.TraceCapture` 对平台 parser 的直接依赖中解开，评测只负责附加 run/case/repeat 上下文。**验证：**server 非评测调用和 Candidate/Judge 分离的 Trace ID/Usage、metadata-only 不泄漏用户内容、撤销后停止上报的回归测试通过。

## 5. Prompt 选择与审计（R4）

- [ ] 5.1 集中 Version/Label 优先级和 requested/resolved/source/fallback 的现有含义，减少 CLI、Provider 与评测包装器的重复解释。**验证：**本地、远程标签、固定版本、精确缓存、线上回退、strict eval 失败、取消/超时传播及 Token 脱敏测试与基线一致。
- [ ] 5.2 审计模板 hash、渲染后内容 hash 和报告当前 `prompt_content_hash` 的实际口径，收敛重复计算但不修改旧字段语义；如需新增/更名持久字段，先独立出 spec。**验证：**相同 Workspace/Key/Version/变量的解析与内容摘要基线比较及变量/history 格式测试通过；文档定义 hash 所代表内容，不泄露 Prompt 原文。
- [ ] 5.3 为 GetPrompt/PromptFormat、Graph 构建和授权检查记录低敏性能基线，只对已证实的热点提出单独的缓存优化建议。**验证：**基线可复跑、不会保存用户原文；未经证实的性能假设不引入新缓存。

## 6. 平台流程与窄用例（R5）

- [ ] 6.1 审查 HTTP adapter 的同源重定向、HTTPS/loopback、分页/响应上限、凭据脱敏、逐请求内容授权，抽取有两个以上真实使用点的共同安全实现，保留元数据/内容载荷区分。**验证：**数据集、Validate/Debug、实验的 fake HTTP 安全矩阵和取消/撤销测试逐项一致。
- [ ] 6.2 让数据集同步用例封装已验收的版本快照/身份核验、pending 写入/恢复与报告状态；CLI 和后续实验只消费验证结果。**验证：**双 run、repeat、部分写入、远端额外 item、content_omitted、版本冲突和旧 pending 的 fake HTTP/本地回归通过，不发生额外上传。
- [ ] 6.3 让评估器发布用例封装现有 Validate→BatchDebug→显式固定版本发布→读回与冲突流程，清除与 CLI 重复的编排。**验证：**离线 validate 不需凭据；publish 缺少显式确认不创建 Client；同版本同内容复用、异内容拒绝、并发保护和字段最小化测试通过。
- [ ] 6.4 在已实现并验收的实验用例上收敛提交、未知响应恢复、分页轮询、逐 item 回关联的流程；保留独立于本地质量的状态。**验证：**fake HTTP 注入超时/重复/缺失/部分结果，且目标 Workspace 小规模运行能对应同一 `run_id + case_id + case_version + repeat_index`；不重跑 Agent。
- [ ] 6.5 在已实现并验收的 A/B 上收敛两 run 可比性校验与逐 case 对比，不依赖页面顺序或平台汇总的隐式过滤。**验证：**同条件和差异模型/参数、缺失/无效 case、不同 repeat 的测试与既有 A/B 报告及人工决策记录一致。
